# contact-sales-shadow-ban

お問い合わせフォームに送られてくる特定ドメインからの営業メッセージを、Google Tag Manager（GTM）だけで相手に気づかれないようにブロックするスクリプトです。

- メールアドレスのドメインがブラックリストに一致したら、フォームを送信せずに完了ページへリダイレクトします
- 相手には通常どおり送信完了したように見え、こちらにはデータが届きません（シャドウバン）
- バックエンド不要です。STUDIO・Wix・WordPress など、GTM を入れられるサイトならどこでも使えます
- エラーが起きた場合は通常どおり送信されます（fail-open）。フォームが使えなくなることはありません

> AI エージェント（Claude Code など）でセットアップする場合は [AGENTS.md](./AGENTS.md) を読ませてください。

## 設定項目

| 設定 | GTM 変数名 | 変数の種類 | 例 |
|---|---|---|---|
| ブラックリスト（ドメインかアドレス） | `営業ブロック - ドメイン` | カスタム JavaScript | 下記 |
| 完了ページの URL | `営業ブロック - 完了URL` | 定数 | `/thanks` または `/contact=/contact/completed, /support=/support/completed` |
| メール欄のセレクタ | `営業ブロック - メールセレクタ` | 定数 | `input[type="email"]` |

ブラックリストは 1 行に 1 つずつ並べた配列を返すカスタム JavaScript 変数です（GTM の定数は 1024 文字までなので、件数が増えても入るようにしています）。

```js
function () {
  return [
    'example-sales.co.jp',
    'spam.jp',
    'sales-bot@example.net',
  ];
}
```

完了 URL は 1 つだけ書くと全ページ共通になります。`フォームのページのパス=完了 URL` をカンマ区切りで書くと、**書いたページのフォームだけ**が対象になり、ページごとに違う完了ページへ移ります。サイト内にほかのフォームがある場合は、こちらの書き方を使ってください。

## セットアップ

### 方法 1：インポート（おすすめ）

1. `config.json` を編集します。リポジトリを公開している場合は、実際のリストを `config.local.json`（git 管理外）に書いてください。ビルドは `config.local.json` があればそちらを優先し、`gtm/container.local.json` を出力します

   ```json
   {
     "domains": ["example-sales.co.jp", "spam.jp", "sales-bot@example.net"],
     "redirectUrl": {
       "/contact": "/contact/completed",
       "/support": "/support/completed"
     },
     "emailSelector": "input[type=\"email\"]"
   }
   ```

   `redirectUrl` は全ページ共通なら `"/thanks"` のように文字列で書きます。

2. ビルドします（Node.js 18 以上。依存パッケージはありません）

   ```bash
   node scripts/build.mjs
   ```

   `gtm/container.json`（`config.local.json` から作ったときは `gtm/container.local.json`）と `dist/demo.html` が生成されます。

3. `dist/demo.html` をブラウザで開いて、ブロック対象のアドレスでは「ブロックされました」、それ以外では「通常送信されました」と表示されることを確認します
4. GTM の「管理」→「コンテナをインポート」で、生成された JSON を選び、ワークスペースを選んで「**統合**」でインポートします
   - 最初は「上書き」が選ばれています。そのままだと既存のタグがすべて消えるので、必ず「統合」に切り替えてください
   - 初回は「競合するものの名前を変更」、2 回目以降の更新は「競合するものを上書き」を選びます。更新時は、プレビューが「営業ブロック - …」の更新だけ（追加 0・削除 0）になっていることを確認してから追加します
5. GTM の「プレビュー」で実際のフォームを確認してから「公開」します

### 方法 2：手動

1. GTM で「変数」→「ユーザー定義変数」→「新規」から、上の表のとおり変数を 3 つ作ります。変数名は表の名前と完全一致させてください
2. 「タグ」→「新規」→「カスタム HTML」に [`src/tag.html`](./src/tag.html) の中身を貼ります
3. トリガーは「DOM Ready」にします（フォームのあるページに絞っても OK）
4. プレビューで確認してから公開します

## ブラックリストにドメインを追加する

GTM の変数 `営業ブロック - ドメイン` を開き、`return [` の中に `'newdomain.co.jp',` の行を足して**公開**するだけです。

- サブドメインも対象になります（`example.co.jp` を登録すると `mail.example.co.jp` もブロック）
- `gmail.com` などのフリーメールから来る営業は、`'sales-bot@example.net',` のようにアドレス単位で書きます

リポジトリでも管理している場合は、`config.json`（または `config.local.json`）の `domains` を更新して `node scripts/build.mjs` を実行し、方法 1 の手順（統合・競合するものを上書き）でインポートしてください。

## 設定のコツ

- 完了 URL は通常送信したときに表示される完了ページと同じにしてください。見た目が違うと相手に気づかれます。STUDIO の完了表示が同じページ内のメッセージの場合は、それと同じ見た目の完了ページを別に用意してください
- メール欄のセレクタはフォームのメール欄を右クリック →「検証」で確認します。たいていは `input[type="email"]` で動きます。1 ページに複数のフォームがあり、メール欄を区別したい場合は `input[name="email"]` のように絞ってください
- `gmail.com` などのフリーメールのドメインは登録しないでください。一般の問い合わせまで届かなくなってしまいます。アドレス単位で登録してください

## 制限事項

- ブラウザを経由せず、フォームの送信先に直接 POST してくるツールはブロックできません
- ブラックリストはページの JS に平文で載ります（見ようと思えば見られます）
- サイトの HTML 構造が大きく変わるとブロックできなくなる可能性があります。フォームを改修したらプレビューで再確認してください
