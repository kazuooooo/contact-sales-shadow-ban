# ハンドオフ：GTMへの導入と動作確認

クラウドセッションで実装まで終わったものを、ローカル PC のセッションで導入・確認するための引き継ぎメモです。
作業の進め方とルールは [AGENTS.md](../AGENTS.md) に従ってください。ユーザーとのやり取りは日本語です。

## 背景

- 会社のお問い合わせフォーム（**STUDIO** で作成、バックエンドなし）に、毎週同じ会社から営業が来る
- GTM のカスタム HTML タグで、メールアドレスのドメインがブラックリストに一致したら**送信を止めて完了ページへリダイレクト**する（シャドウバン）
- 判定はドメインだけにする（社名は表記揺れと誤爆があるので使わない）。ブラックリストは平文で構わない（ハッシュ化は不要と判断済み）
- 設定は GTM の定数変数 3 つで持つ。ブラックリストを追加するときは GTM の変数を書き換える運用（スプレッドシート連携は採用しない）

## 完了していること

- `src/tag.html`、`scripts/build.mjs`、`config.json`、README、AGENTS.md を実装して `main` にプッシュ済み
- `dist/demo.html` で次の 4 パターンが期待どおりに動くことを Playwright で確認済み
  - ブロック対象のドメイン：ブロックされる
  - ブロック対象のサブドメインで大文字混じり（Enter キーで送信）：ブロックされる
  - 名前が似ているだけの別ドメイン：通常送信される
  - 無関係なドメイン：通常送信される
- ビルド時の検証が動くことを確認済み（不正なドメインならエラー終了、フリーメールなら警告）

## 未確認のこと（このセッションでやること）

- [x] `gtm/container.json` が実際の GTM にインポートできるか（2026-11-21 確認。`container`・`usageContext`・`fingerprint` を足して取り込めるようにした。定数は 1024 文字までなので、ドメインはカスタム JavaScript 変数にした）
- [x] 実際の STUDIO のフォームで、セレクタ `input[type="email"]` が合っているか（実際のフォームのページで一致）
- [x] STUDIO の送信処理を click / submit のキャプチャで止められるか（STUDIO 本体とサイト独自のスクリプトの両方より先に止まる）
- [x] 本番に公開したあとの動作（本番の gtm.js で確認）

## 作業手順

### 1. ユーザーに確認する

- お問い合わせフォームがあるページの URL
- ブロックしたいドメイン
- 完了ページの URL。STUDIO で通常送信したときの遷移先を聞く。同じページ内にメッセージが出るだけの方式なら、同じ見た目の完了ページを用意する必要があると伝える
- GTM のコンテナ ID（`GTM-XXXXXXX`）。そのサイトに GTM がすでに入っているかも確認する

### 2. 設定してビルドする

`config.json` を更新して `node scripts/build.mjs` を実行する。

### 3. 公開前に実際のフォームで確認する

ブラウザでお問い合わせページを開き、`src/tag.html` の GTM 変数を実際の値に置き換えたものをコンソールなどから差し込んで試す。

- ブロック対象のアドレス：完了 URL に遷移し、送信リクエストが出ないこと
- 通常のアドレス：送信処理に進むこと

**通常のアドレスで試すときは、実際の送信リクエストを止めること**（Playwright の `page.route` で abort するなど）。止めないとテストの問い合わせが会社に届く。

### 4. GTM に導入する

ユーザーのブラウザ（Claude in Chrome か内蔵ブラウザ）で GTM を操作する。

- 「管理」→「コンテナをインポート」→ `gtm/container.json` →「既存のワークスペース」か新しいワークスペース →「統合」→「競合するものの名前を変更」
- インポートに失敗したら、README の「方法 2：手動」で導入する。あわせて `scripts/build.mjs` のコンテナ JSON の形式を直してコミットする
- Google のログインや 2 段階認証が出たら、ユーザーに入力してもらう

### 5. プレビューで確認してから公開する

- GTM の「プレビュー」で、3 と同じ確認を実際のサイトでやる（このときも通常のアドレスでは送信しない）
- **公開する前に必ずユーザーの確認を取る**（本番サイトに影響するため）
- 公開後、本番ページで GTM のタグが読み込まれていることと、ブロック対象のドメインでブロックされることを確認する

### 6. 後片付け

- 結果をユーザーに報告する。確認できたこと・できなかったことを分けて書く
- 修正したファイルがあればコミットしてプッシュする

## 今後の改善案（任意）
